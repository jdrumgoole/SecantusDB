### A spilled `$group` writes mongod's file and merges as mongod does

When a classic `$group` passes its memory budget, mongod sorts the groups it holds by key and writes them to a sorter file. Each group is one record: its key, then each accumulator's state in the form mongod uses to merge partial results. At the end it reads the runs back key by key into fresh accumulators. The Rust MongoDB server spilled the same groups as BSON documents of its own, so it reported about twenty times mongod's `groupSpilledDataStorageSize`: 320100 bytes for a `$push` of 300 1000-byte strings, where mongod 8.2 stores 16321. It now writes mongod's records into the chunked, snappy-compressed file its sorter already shares with mongod. A sum is `[type, sum, addend]` with the decimal total when there is one, an `$avg` is `{count, ps}`, a standard deviation is Welford's `{m2, mean, count}`, and a `$topN` keeps `{generatedSortKey, output}`. A compound `_id` is an array of its fields, and a missing value is a single type byte. It reads them back the way mongod merges: a standard deviation combines its runs by the parallel algorithm, and a `$maxN` with ties comes out in the order mongod's merge gives. `$push`, `$avg`, `$stdDevPop`, `$min`, `$max`, `$addToSet`, `$mergeObjects` and `$first` now report mongod's size to the byte.

Some sizes still differ. A `$setWindowFields` spills to a file where mongod uses a WiredTiger table, and `$median` keeps its values where mongod writes a t-digest (both RM-325). A `$first`, `$last`, N accumulator or object `_id` counts its memory unlike mongod, so it spills at other points (RM-502).

#### Fixed

- `secantus-core` (`group_spill`, `group`, `spill_file`): the classic `$group` spills mongod 8.2's `GroupProcessor::spill` records through `spill_file::Writer`. The key is a `Value`, and a compound object `_id` is an array of its fields with a missing one missing, sorted by mongod's comparator. The accumulators follow it as `getValue(toBeMerged)`: none, one, or an array of them. They are read back by `process(state, merging)` into fresh accumulators, in run order. `groupSpilledDataStorageSize` is the bytes written. `$first` / `$last` now keep a missing value apart from null, as mongod does, and output null for both. The SBE `$group` keeps this server's own format.
- `secantus-core` (`group`): a `$sum`'s width is now mongod's `nonDecimalTotalType`, and a decimal total is marked by the decimal sum being present. This is what the spilled partial sum carries.
- Fixes RM-325's `$group` half (tests/backlog/test_rm_found_2026_10_26.py::test_group_spill_storage_size). The item stays open for the `$setWindowFields` spill (`test_spill_storage_size`).
- Regression tests: `group_spill::tests::a_classic_spill_writes_mongods_sorter_records_and_merges_them`, and `group_spill::tests::a_spilled_group_gives_the_same_groups_in_key_order` (a merged `$stdDevPop` agrees to its last digits).
- Filed RM-502: a classic `$group` counts its held values' and an object `_id`'s memory unlike mongod (`test_group_held_value_spills`).
