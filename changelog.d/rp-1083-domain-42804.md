### Rust PG server: a 42804 assignment error names a domain column by its domain

An expression of the wrong type assigned to a domain column now reports the
column as PostgreSQL does, by the domain's own name (`column "p" is of type
pint48 but expression is of type text`), where it printed the domain's base
type (`integer`).

#### Fixed

- `INSERT ... VALUES`, `UPDATE ... SET`, `INSERT ... SELECT` and a column
  `DEFAULT` that fail their assignment coercion into a domain column (a
  domain over an array included) name the domain, schema-qualified when it
  is outside the `search_path`, as `format_type_be` prints the column's
  `atttypid`.

Fixes RP-1083 (tests/backlog/test_rp_found_rp1048.py::test_domain_column_named_in_42804)
