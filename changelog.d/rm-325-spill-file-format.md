### A spilled sort takes the bytes on disk that mongod's does

When a sort passes its memory budget, mongod writes its sorted runs to a spill file, and the profiler, `explain` and `serverStatus` report the file's size as `spilledDataStorageSize`. The Rust MongoDB server spilled the same runs, records and bytes, but wrote them as uncompressed BSON, so it reported about twenty times mongod's figure: 2480400 bytes where mongod 8.2 reports 130545. Its sorter now writes mongod's file. Each record is in mongod's own `serializeForSorter` form, the records go into 64 KiB chunks, and each chunk is snappy-compressed by a port of the compressor mongod builds in (snappy 1.1.10, with its CRC32-C hash), or stored as it is when compression saves less than a tenth. A query-layer sort, a pipeline `$sort` and `$bucketAuto` now report mongod's size to the byte whenever the sorter sees its documents in the order mongod's does. The size was checked by decoding mongod's own spill file, copied out of `_tmp` while a cursor held it open.

Some spills still differ, and each is on the backlog. A classic `$group` writes this server's own partial states, and a `$setWindowFields` uses a file where mongod uses a WiredTiger table (RM-325). A sort that reorders the documents a scan reads is fed them already sorted, so it spills different runs (RM-395).

#### Fixed

- `secantus-core` (`sorter`, new `spill_file`, new `snappy`): a sort's runs are written as mongod 8.2's `SortedFileWriter` writes them. A record is a `Value` key (an array for a compound sort), then the document: as BSON for the query layer's sort, as a `Document` of the fields kept for a pipeline `$sort`, and inside `{output, generatedSortKey}` for `$bucketAuto`. Records go into 64 KiB chunks, each prefixed with its signed `int32` length and snappy-compressed when that saves a tenth. `spilledBytes` is now the bytes before compression, and `spilledDataStorageSize` and `metrics.query.sort.spillToDiskBytes` are the bytes written. Records convert from this crate's BSON and back byte for byte, so strings that are not UTF-8 and escaped field names survive a spill. The file's size on disk is checked against what was written.
- Partly fixes RM-325 (tests/backlog/test_rm_found_2026_10_26.py::test_spill_file_storage_size). The item stays open for the `$group` and `$setWindowFields` spills (`test_spill_storage_size`).
- Regression tests: `sorter::tests::spills_and_merges_count_as_mongods_do` (130545 bytes, merges included), `sorter::tests::a_spill_file_takes_what_mongods_takes`, `spill_file::tests::*` and `snappy::tests::*` (the CRC matches the arm64 `__crc32cw` instruction).
- Filed RM-395: a query-layer sort is handed documents already sorted, so it spills different runs from mongod's (`test_leading_sort_spill_storage_size`).
- Filed RM-396: a `$sort` after `$addFields` spills at slightly different record boundaries (`test_added_fields_sort_spill_storage_size`).
- Filed RM-397: a `$group` of `$sum` and `$count` counts 16 bytes a group less memory than mongod (`test_group_sum_spilled_bytes`).
