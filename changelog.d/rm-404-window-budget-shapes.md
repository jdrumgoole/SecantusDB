### Windows with no lower end, `$min`, `$max`, `$expMovingAvg` and `$locf` held to mongod's budget

A `$setWindowFields` window with no lower end never lets a value out of its accumulator, so mongod lets documents go as soon as the window has read them. It keeps only what the window has still to read and the document being answered. The Rust MongoDB server held the whole partition for a `range` window like that, so `["unbounded", 4]` over 40 small documents needed 5184 bytes against mongod's 684 on a Mac (676 on Linux). It now releases documents as mongod's partition iterator does. A `range` window lets go of what lies left of the right end it found for the document before. A `documents` window lets go of what lies left of its upper end. A `range` window that ends at `"current"` no longer reads past the document it answers. The functions now also count what mongod counts. A removable `$min` or `$max` holds each value twice, once in its executor's queue and once in its sorted multiset, and nullish values only in the queue. `$expMovingAvg` counts its own 136 bytes. `$locf` counts 128 bytes plus the buffer of the value it carries. All four shapes in the item now run under mongod's least budget to the byte, with and without `partitionBy`.

#### Fixed

- `secantus-core` (`windowfields::reach`): a window with no lower end keeps the documents mongod's `kRightEndpoint` (`range`) and `kDefaultSequential` (`documents`) policies keep (`partition_iterator.h`, r8.2.1). A `range` window's `"current"` upper end reads no further than the document answered.
- `secantus-core` (`windowfields::FunctionMemory`, `memlimit::Layout`): `removable_min_max` (macOS arm64 112, Linux 128), with every value that is not nullish counted twice. `$expMovingAvg` counts 136 bytes, and `$locf` 128 plus its carried value's heap.
- Fixes RM-404 (tests/backlog/test_rm_found_2026_11_08.py::test_window_budget_more_shapes, and the new tests/backlog/test_rm_found_2026_11_08.py::test_window_budget_unbounded_lower_shapes over ten more shapes, whole and partitioned).
- Filed while working it: RM-508 (a `range` window's `"current"` takes in tied documents, which is a wrong answer), RM-509 (`$integral` and the covariances count no memory) and RM-510 (a partitioned window's `maxTotalMemoryUsageBytes` is off by 16 bytes).
