How do you know it's right? You run it against the real server.

One exemplar. mongod 8.x for the MongoDB server and PostgreSQL for the SQL server. Never another SecantusDB server, never our own docs.

Differential probes. The same pymongo code against SecantusDB and against real mongod; diff the answers, including the BSON types, not just the values.

Parity isn't correctness. Our Python and Rust servers once agreed on $bucket, $densify and $stdDev, and both were wrong. Tell the $asinh story briefly: two of our own engines agreed, mongod disagreed, and mongod is right by definition.

Every real bug in the August sweeps came from executing behaviour and comparing, not from reading code. Estimates from reading code were wrong in both directions.
