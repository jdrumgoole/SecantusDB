The motivation: we didn't have to invent a client ecosystem or a storage engine.

The clients exist. pymongo, psycopg, SQLAlchemy and official drivers in a dozen languages. If you speak their wire protocol correctly, they all just work, and their authors have already written thousands of tests describing what a server must do.

The engine exists. WiredTiger gives us checkpoints, transactions and durability. We don't write B-trees or a write-ahead log.

The gap is the server in between: one small, self-contained server that is faithful to the real products, starts in one line and needs nothing else installed. All the hard work is in being faithful.

Then walk the two rows: that's the server in between.

MongoDB: pymongo sends OP_MSG; secantus-wire turns it into commands; secantus-core runs the query, update and aggregation engines; secantus-storage talks to WiredTiger.

PostgreSQL: psycopg speaks the PG wire protocol; libpg_query, PostgreSQL's own parser, parses the SQL; secantus-pgplan lowers it to the filters the core engine evaluates; and it lands in the same tables, in the same files.

It's a Cargo workspace of about 20 crates. The engines have no PyO3, so the standalone binaries and the Python bindings share them.

A CREATE TABLE in the Postgres server reads back as a collection in the MongoDB server. That's a hand-off, not concurrent serving: WiredTiger's file lock lets only one server open the directory at a time.
