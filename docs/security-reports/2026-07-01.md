## 🟠 WARNING (Address within 1 week)

### W1 — `Storage.close()` silently swallows checkpoint/session/connection-close errors

**File:** `src/secantus/storage.py:2200-2220`

The final teardown block in `close()` wraps the persisted oplog-meta write, the last checkpoint, each WT session's `close()`, and `self._conn.close()` in bare `contextlib.suppress(Exception)` — with **no logging at all**:

```python
with contextlib.suppress(Exception):
    self._persist_oplog_meta()
with contextlib.suppress(Exception):
    self._session.checkpoint()
...
with contextlib.suppress(Exception):
    session.close()
with contextlib.suppress(Exception):
    self._conn.close()
```

This directly contradicts CLAUDE.md's "Never ignore an error — this is a database" section, and is inconsistent with the rest of the same file: the TTL-sweep loop and the noop-heartbeat loop both call `log.exception(...)` before continuing past a caught error. A checkpoint failure on the final flush before shutdown — exactly the kind of event the project's own philosophy calls a durability signal — is discarded with zero trace, giving the embedder no way to know the last durable image may be incomplete.

**Fix:** Replace the bare `contextlib.suppress(Exception)` calls in the `close()` teardown with a pattern that logs the exception (`log.exception(...)` or equivalent) before continuing, matching the TTL/heartbeat loops elsewhere in the same file.

### W2 — Rust `cstr()` panics on an embedded NUL byte in wire-supplied db/coll/index names, dropping the connection with no wire-level error reply

**Files:** `crates/secantus-wt/src/lib.rs:489-490`, `crates/secantus-commands/src/lib.rs:421-427`, `crates/secantus-server/src/lib.rs`

```rust
// crates/secantus-wt/src/lib.rs:489-490
fn cstr(s: &str) -> CString {
    CString::new(s).expect("string has interior NUL")
}
```

`cstr()` is used by `set_key_s`/`set_key_ss`/`set_key_ssu`/`set_key_ssq`/`set_key_sss`, which are called throughout `secantus-storage` with client-supplied `db`/`coll`/`index_name` strings that originate from BSON command documents. BSON strings are length-prefixed and can legally contain an embedded NUL byte. `secantus-commands`'s namespace validation (`lib.rs:421-427`) only rejects components over 63 bytes — there is no NUL-byte check before these values reach `secantus-wt`.

Note that the *same file* already has the correct pattern elsewhere (`Session::create`/`open_cursor`, lines 171/179, use `CString::new(...).map_err(nul_err)?`) — it just isn't applied to `cstr()`.

Compounding this, **the Rust server has no `catch_unwind` anywhere in the wire/dispatch path**. A panic in `cstr()` unwinds only the per-connection thread (the process survives — each connection is `thread::spawn`'d independently), but the socket is dropped with no `{ok:0, errmsg, code, codeName}` reply, unlike the Python server, which catches every `Exception` in `dispatch` and every parse error in the connection loop. This is the same class of bug as the previous report's W4 (OP_QUERY NUL-termination, now fixed on the Python side) — a client-triggerable per-connection DoS via a well-formed BSON command, not a memory-safety issue, but a discipline gap against the "every error surfaces as `{ok:0,...}`, connection survives" contract.

**Fix:** Make `cstr()` return `Result<CString, _>` (or reject embedded-NUL db/coll/index names during BSON command validation in `secantus-commands`, before they reach `secantus-wt`) instead of panicking. As defense-in-depth, wrap the per-connection dispatch call in `std::panic::catch_unwind` so any *future* unguarded panic still produces a wire-level error reply rather than a silent disconnect.

### W3 — Admin `HistoryStore` persists raw credentialed `mongo_uri` to disk instead of a scrubbed form

**Files:** `src/secantus/admin/history.py`, `src/secantus/admin/routers/query.py:188-192,242-246,292-296`, `src/secantus/admin/backup.py:99,155`

`HistoryStore` (backed by `~/.secantus/admin.db`) and its call sites in `query.py` all pass `request.app.state.mongo_uri` — the **raw**, potentially credentialed URI (e.g. `mongodb://user:pass@host/`) — as the stored `uri` column, rather than the already-available scrubbed `display_uri()` form used elsewhere in the codebase for rendering. The same raw value is passed into backup/restore snapshot operations (`backup.py`).

The value is only used as a lookup key today and was not found rendered back into any template (confirmed by grepping `templates/` for the relevant context keys), so this is not a live XSS/leak in the running UI — but it does mean a plaintext-credentialed connection string sits in a queryable SQLite file on disk, readable by any other process running as the same local user, and would appear verbatim in any backup/dump of `admin.db`. This is precisely the pattern flagged by the review checklist's own admin-UI item ("must not log or render stored URIs with embedded credentials") — the render half is clean; the persist/log half is not.

**Fix:** Store the scrubbed `display_uri()` form (or a separately-hashed/opaque identifier) in `HistoryStore` and any backup/restore metadata, never the raw credentialed URI.

### Top 3 priorities

1. **Fix the Rust `cstr()` NUL-byte panic and add a `catch_unwind` boundary around per-connection dispatch** (W2) — this is the same class of bug as last cycle's headline fix (W4): a well-formed BSON command containing an embedded NUL byte in a db/coll/index name currently kills a connection with no wire-level error reply on the Rust server, where the Python server already handles the equivalent case correctly.

2. **Stop persisting raw credentialed URIs in the admin query-history store** (W3) — `HistoryStore` and the backup/restore path both write `mongo_uri` (not the scrubbed `display_uri()` form) to `~/.secantus/admin.db`; switch to the scrubbed form used everywhere else in the admin UI.

3. **Log (don't silently suppress) errors in `Storage.close()`'s final teardown** (W1) — a checkpoint or connection-close failure at shutdown is currently discarded with zero trace, which is exactly the kind of durability signal CLAUDE.md's own philosophy says must never be swallowed.
