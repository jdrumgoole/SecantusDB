- **W1 (carried forward)** — `uv.lock:525-536` still pins
  `cryptography==48.0.0`, two full patch versions behind the fix (`49.0.0`)
  for **CVE-2026-69248** (wildcard-DNS name-constraint escape in the X.509
  path verifier) and **CVE-2026-69249** (exponential path-building DoS on a
  malicious certificate chain), both re-confirmed live this cycle via
  WebSearch. Still dev-only (`trustme`'s transitive dependency, never
  imported by shipped code), still no countervailing reason not to bump.
  `uv.lock` unchanged this window. Not fixed. Issue **#1023** open.
- **W2 (carried forward)** — `tools/build_lz4_macos.sh` (unchanged this
  window) still downloads the `lz4/lz4` v1.10.0 release tarball over HTTPS
  with no checksum/signature verification, in the macOS wheel's
  `cibuildwheel` `before-build` step — the one path that ships to PyPI. Not
  fixed. Issue **#1024** open.
- **W3 (new)** — Unbounded per-namespace metrics map, both engines. The new
  `top` command (`src/secantus/metrics.py`'s `Metrics.ns_top`;
  `crates/secantus-commands/src/topstats.rs`'s `TopStats.inner`) creates one
  dict/`HashMap` entry per distinct `db.collection` string the very first
  time any namespaced command (`find`, `insert`, `count`, …) names it —
  including a collection that does not exist, since the accounting happens
  in `dispatch`/`run_dispatch` after the handler returns, independent of
  whether the command succeeded. There is no cap on distinct namespaces, no
  idle-TTL pruning, and no length limit on the collection-name string beyond
  the ordinary BSON document/message-size ceiling (`MAX_BSON_OBJECT_SIZE` =
  16MiB, `MAX_MESSAGE_SIZE` = 48MB in `wire.py`) — contrast the cursor
  registry, which has an explicit `DEFAULT_MAX_CURSORS = 10_000` cap plus a
  600s idle-TTL prune. The only eviction path is a *successful* `drop` on
  that exact namespace (`forget_namespace`/`TopStats::forget`), so querying
  many distinct nonexistent-collection names accumulates permanently.
  `Metrics()` is unconditionally constructed on every `SecantusDBServer`
  (`server.py:196`) and `TopStats::new()` unconditionally on every Rust
  `bind()` — this is not an opt-in feature, every deployment carries it. The
  auth gate (`ctx.require_auth`) returns before the handler runs and before
  this accounting block, so it's not reachable by an unauthenticated
  connection when `--auth` is on — but `--auth` is off by default, and an
  unauthenticated client can freely issue `find` against arbitrarily many
  distinct collection names (real or not) to grow the map without bound. A
  sustained stream of small requests (or fewer requests with large
  collection-name strings near the 16MiB document cap) is a memory-
  exhaustion DoS with no cap and no recovery short of a restart. Less severe
  than #1037/#995 (needs repeated requests, not one frame), comparable in
  shape to the already-tracked #949 (PG portal-count cap) — same "new
  feature added an unbounded per-key accumulator with no cap" pattern.
  New issue filed this cycle: **#1073**.
- **#976** — `src/secantus/sql/pgauth.py:65-78` (`mock_credentials`): still
  `iteration_count=4096, salt=os.urandom(16)` for a fabricated unknown-user
  verifier vs. real users' `default_iterations=15000, salt_bytes=28`
  (`auth.py:52-68`) — a user-enumeration oracle on the SQL surface's only
  auth control. File unchanged this window. Not fixed.
- **#977** — `src/secantus/query.py:1082-1089` (`_MAX_REGEX_PATTERN_LEN`,
  `_compile_regex`): still only a 1000-char pattern-length cap on the bare
  `re.compile()` call, no timeout/complexity/backtracking-depth guard. This

- **#978** — `.github/workflows/rust-wheels.yml`: `permissions:` appears
  exactly once (the `publish` job); the `build` and `sdist` jobs above it
