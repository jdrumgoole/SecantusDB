- **C8 (new)** — **`bulkWrite` bypasses RBAC authorization entirely, on both
  servers.** MongoDB 8.0's client-level `bulkWrite` command landed this
  window (`36668ac4` Python, `f15d6581` Rust) as a new top-level handler on
  both engines, but neither engine's privilege table was updated to include
  it:
  - **Python** — `src/secantus/commands.py:7875` registers `"bulkWrite":
    _bulk_write` in the handler table, but `_COMMAND_ACTIONS` (line 7960,
    the RBAC action table listing `insert`/`update`/`delete`/
    `findAndModify`/etc.) has **no `"bulkWrite"` entry**, and `bulkWrite` is
    also absent from `_NO_PRIVILEGE_COMMANDS` (line 8050, the explicit-
    exemption set). Directly re-read the dispatch privilege-check block at
    line 8873-8899: `info = _COMMAND_ACTIONS.get(name)`; `if info is not
    None:` — when `info` is `None` (as it is for `bulkWrite`), the entire
    `check_privilege(...)` call is skipped, unconditionally, for every
    caller. `_bulk_write` (line 3038) then calls `_insert`/`_update`/
    `_delete` **as bare Python functions** on a rebound `sub_ctx` (one per
    op, per its own target namespace from `nsInfo`), never re-entering
    `dispatch()`, so there is no secondary check either — confirmed those
    three handler functions perform no privilege check of their own (only
    `dispatch`'s single block does, for top-level `insert`/`update`/
    `delete`). The only surviving guard is `_reject_oplog_rs_write` (blocks
    `admin.system.users`/`local.oplog.rs`).
  - **Rust** — `crates/secantus-commands/src/lib.rs:405` registers
    `"bulkWrite" => bulkwrite::bulk_write` in the dispatch table. Directly
    re-read `command_action()` (line 1518-1569, the Rust equivalent of
    Python's `_COMMAND_ACTIONS`): its `match` arms cover `find`/`insert`/
    `update`/`delete`/... through `configureFailPoint`, ending in `_ =>
    return None`. **No `"bulkWrite"` arm.** The privilege check at line 1403
    (`if let Some((action, scope)) = command_action(name) { ... }`) is an
    `if let` — when `command_action` returns `None`, the whole block is
    skipped, identically to the Python side. `bulk_write()` (`bulkwrite.rs:
    70`) calls `crud::insert`/`update`/`delete` as bare functions (lines
    207-209), bypassing `dispatch_inner` entirely, so there's no per-op
    check either.
  - **Impact:** under `--auth` on either server, an authenticated principal
    with **no grants at all** (or grants scoped to an unrelated database) can
    call `admin.bulkWrite` with an `ops`/`nsInfo` list naming any namespace
    and insert, update, or delete documents there — a full authorization
    bypass for the write path, on both engines, introduced by the same
    feature landing simultaneously in both codebases. This is a different
    root cause from the standing SQL-authz-dispatch-gap class (#909/#947/
    #948/#996/#1118): those are SQL-surface statement kinds missing from a
    Postgres-style RBAC dispatch; this is the *Mongo*-surface RBAC table
    (used by both servers identically) missing an entry for a brand-new
    top-level command, the same bug shape as the `dbStats`/`getParameter`
    gaps already fixed and documented in-line at `commands.py:7993-7996` and
    `8022-8026` (both explicitly comment on "the dispatcher silently exempts
    commands missing from this table" as a known hazard) — `bulkWrite`
    joined that table without being added to it.

- **C9 (new)** — **Two more unbounded-recursion-in-error-rendering
  instances land this window, extending the #1117 bug class, on paths more
  directly wire-reachable than the original two:**
  - `crates/secantus-core/src/aggregate.rs:286` (`render_value_compact`,
    new this window) recurses into `Bson::Array`/`Bson::Document` with no
    depth cap (lines 320-333: `a.iter().map(render_value_compact)...`, `d.
    iter().map(|(k,v)| ... render_value_compact(v))`). It is called from
    `redact_runtime_error` (line 351) to render mongod's `17053` error when
    a `$redact` expression evaluates to a non-`$$KEEP`/`$$PRUNE`/`$$DESCEND`
    value. **Trigger:** `aggregate([{$redact: {$literal: <a BSON array
    nested tens of thousands of levels deep>}}])` against a collection with
    at least one document — no auth, no prior state beyond one document
    existing in the target collection.
  - `crates/secantus-core/src/aggregate.rs:264` (`redact_list`, new this
    window) widens `$redact`'s array handling to recurse into *nested*
    arrays via a `redact_subdoc`/`redact_descend`/`redact_list` mutual
    recursion (previously a dead end — nested arrays were copied verbatim
    and never walked). This is a **second, independent** unbounded-recursion
    surface: even when every value in the document *is* a proper `$$KEEP`/
    `$$PRUNE`/`$$DESCEND` decision (so `render_value_compact` above is never
    reached), a document containing a self-nested array deep enough
    recurses the evaluator itself past the stack limit.
  - `crates/secantus-commands/src/bulkwrite.rs:67` (`render_op`) and
    `bulkwrite.rs:121` (inline) both call the **already-known-unbounded**
    `argtypes::render_stage_value` (the exact function #1117 already
    flags) on brand-new, more directly reachable paths: `render_op` fires
    the moment a `bulkWrite` op entry doesn't contain a supported
    `insert`/`update`/`delete` key (line 130), and the line-121 call fires
    the moment an `ops[]` entry isn't a BSON document at all — reading the
    array entry's raw `Bson` value and stringifying it recursively before
    any other validation runs. **Trigger:** a `bulkWrite` command whose
    `ops` array contains one entry that is itself a deeply-nested BSON
    array (not an object) — the type check that would normally reject it
    calls `render_stage_value` on the offending value first, to build the
    error message.

  All four sites share the same root cause #1117 already names: **no BSON
  nesting-depth cap anywhere on the Rust wire/decode path**, re-confirmed
  this cycle by the same grep for `max_depth`/`MAX_DEPTH`/`recursion_limit`/
  `nesting` across the full `crates/` tree (only unrelated hits: `$graphLookup`'s
  `maxDepth` option, SQL-parser depth counters). A Rust stack overflow
  aborts the whole process rather than unwinding through `catch_unwind` in
  `secantus-server`, so each of these four sites is an independent,
  unauthenticated, single-request denial-of-service on the Rust server — the
  same severity class as #995 and #1117, and new instances of it (three of
  the four call sites — `render_value_compact`, `redact_list`, and both
  `bulkwrite.rs` call sites — did not exist before this window's commits).
  Not filed until this report lands (see "Land the report" below).
