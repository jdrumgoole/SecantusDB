### #995 (carried forward, still open, re-confirmed)

`crates/secantus-wire/src/lib.rs:137-151` (`Header::body_len`) — read in
full again this cycle:

```rust
pub fn body_len(&self) -> Result<usize, WireError> {
    if (self.message_length as usize) < HEADER_SIZE {   // casts to usize BEFORE any sign check
        return Err(...);
    }
    if self.message_length > MAX_MESSAGE_SIZE {           // still-signed i32 compare
        return Err(...);
    }
    Ok(self.message_length as usize - HEADER_SIZE)
}
```

Unchanged byte-for-byte from yesterday. A negative `message_length`
(e.g. wire bytes `FF FF FF FF`) sign-extends to `usize::MAX` under the
first cast, defeating both bound checks, and the caller
(`crates/secantus-server/src/lib.rs:550-559`) then does
`vec![0u8; ~1.8×10^19]`, which aborts the process via
`handle_alloc_error` — a single unauthenticated 16-byte frame kills the
whole Rust server. Not fixed. Tracked as **#995**.
