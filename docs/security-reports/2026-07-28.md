## 🟠 WARNING (Address within 1 week)

### W1 (carried forward, still open — 8th consecutive cycle) — Two non-poison-tolerant `.lock().unwrap()` sites remain on the Rust oplog mutex

**File:** `crates/secantus-storage/src/lib.rs:3878` and `:3957` — re-confirmed present by direct grep this cycle (`grep -n "self.oplog.lock()" crates/secantus-storage/src/lib.rs`, 13 call sites total): every other site uses the poison-tolerant `unwrap_or_else(|e| e.into_inner())` pattern; these two `prune_oplog` accessors (the `live_count` early-out read and its post-prune decrement) still use bare `.lock().unwrap()`.

Already tracked as open issue [#593](../../../../issues/593), filed 2026-07-21, unfixed across **eight** consecutive review cycles (07-21 through 07-28). No commit touched `crates/secantus-storage/src/lib.rs` this cycle.

**Recommendation:** unchanged — convert both sites to `self.oplog.lock().unwrap_or_else(|e| e.into_inner())`. The grep-based CI gate recommended in the last seven reports (`! grep -rn '\.lock()\.unwrap()' crates/secantus-storage crates/secantus-commands` outside `#[cfg(test)]`) remains unimplemented after eight nightly re-discoveries.

### W2 (carried forward, still open — 5th consecutive cycle) — `drop_index` / `drop_all_indexes` still lack the collection lock that `create_index` gained on 2026-07-24

**File:** `src/secantus/storage.py:5617` (`drop_index`) and `:5734` (`drop_all_indexes`) — re-confirmed present by direct read this cycle: both still open only `with self._lock:`, never `self._coll_lock(db, coll)`.

Already tracked as open issue [#635](../../../../issues/635), filed 2026-07-24. No commit this cycle touched `storage.py` — the only recent hit (`bc361fc4`, reviewed 2026-07-27) was the change-stream `read_oplog_scan` fix, unrelated to index-drop locking. The hazard is unchanged: a concurrent `insert`/`update`/`delete` (which takes `_coll_lock` first) is not excluded by `drop_index`'s `_lock`-only critical section.

**Recommendation:** unchanged — `with self._coll_lock(db, coll), self._lock:` in both methods, plus a regression test mirroring `test_ddl_and_crud_never_deadlock_and_index_stays_complete` for the drop path.
