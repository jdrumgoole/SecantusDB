### Rust storage — non-logged oplog tables + drainer batch coalescing (`a6f07c89`, opt-in, off by default)

`SECANTUS_OPLOG_NONLOGGED=1` creates the oplog + preimage tables with WiredTiger `log=(enabled=false)` (checkpoint-durable only, taking the async drainer's WAL off the write-path hot loop), and the drainer now greedily coalesces up to `COALESCE_MAX_BATCHES=32` / `COALESCE_MAX_BYTES=16MiB` of queued batches into a single WT transaction (`SECANTUS_OPLOG_ASYNC_COALESCE=0` to disable). `secantusd-rs` also gains `SECANTUS_DISABLE_OPLOG=1` (previously an embedded-extension-only lever). Reviewed with the same lens as the async-oplog prototype in the 2026-07-26 report (I36/I37), since it's the same durability-tradeoff surface:

- **Locking discipline holds.** Every new/changed lock acquisition on `self.oplog` (`persist_group`'s `advance_written_seq` call) uses the poison-tolerant `unwrap_or_else(|e| e.into_inner())` pattern already established elsewhere in the file — it does not touch, and does not replicate, the two pre-existing non-poison-tolerant sites tracked as W1 below.
- **Coalesced-transaction failure degrades safely, not silently.** `persist_group` attempts one transaction for the whole group; on failure it falls back to `persist_and_record` per batch (the same already-reviewed retry/log path from the synchronous case), so a single poison batch inside a coalesced group can't silently drop the rest — each batch gets its own retry-or-log outcome. `write_drain_batches`' only `.unwrap()` (`pc.as_ref().unwrap()`) is immediately preceded by the `if pre_cur.is_none() { pre_cur = Some(...) }` that makes it structurally infallible, same pattern already reviewed and accepted in the 2026-07-26 report.
- **`Storage::drop`'s drainer-shutdown loop is unchanged this cycle** (still the bare `let _ =` on `tx.send`/`handle.join()` tracked as I36 below) — the diff does not touch that block.
- **New durability-reduction surface is disclosed and, like `SECANTUS_WT_CONFIG_EXTRA` (I37), env-only / not wire-reachable** — `SECANTUS_OPLOG_NONLOGGED`, `SECANTUS_OPLOG_ASYNC_COALESCE`, `SECANTUS_DISABLE_OPLOG` are all read once from the process environment at startup, never from a wire command or client-supplied config. One rough edge not previously called out: `oplog_table_cfg()` applies **only at table-create time** — flipping `SECANTUS_OPLOG_NONLOGGED` against a store whose oplog tables already exist is silently a no-op (no warning that the requested config didn't take effect). Recorded as a new INFO item (I38) rather than WARNING: it's a local operator footgun, not attacker-reachable, and getting it wrong only means "durability is stronger than the operator expected," never weaker than the store's actual on-disk table config.
- No new `unsafe` in this diff; `cargo audit`-relevant surface unchanged except the new `mimalloc`/`libmimalloc-sys` pair (see Dependencies below).

Reviewed and sound; one new INFO item (I38).

### Change-stream event-loss fix (`bc361fc4`) — correctness, not a security boundary

Fixes a real data-loss bug (not exploitable, not attacker-triggered): an empty change-stream poll advanced its cursor to `oplog_tail_seq()` (the highest seq *minted*, not the highest seq *visible*), which could silently skip past an oplog entry a concurrent writer had minted but not yet committed — no later poll could ever recover it. The fix bounds the skip to `scan_high`, the highest seq the poll's own scan actually examined (filtered-out entries included), exposed as `Storage.read_oplog_scan`. Read the full diff: the fix is local to the read-position bookkeeping, touches no auth/parsing/trust boundary, and ships with a regression test that reproduces the original race deterministically (commits a write from inside the producer's own storage call to hit the exact window). Consistent with `CLAUDE.md`'s "never ignore an error — this is a database" principle applied to change-stream delivery guarantees. No security finding; noted for completeness since it touches oplog-position handling, which change-stream resume-token forgery concerns would also live in (none found — resume tokens are still the existing `{s, t, ns, k}` opaque-to-pymongo encoding, unchanged).

Two new build-time PGO paths, both reviewed for the two things that matter here: does either fetch/execute untrusted remote code, and does either mis-handle CI secrets or attacker-controlled input.

- **Embedded extension (`CMakeLists.txt`):** extracts the already-committed, already-reviewed `crates/pgo/_secantus_server.profdata.tar.gz` via `cmake -E tar xzf` (no network fetch) and passes it to `cargo` via `-Cprofile-use` in a composed `RUSTFLAGS` string built entirely from CI-internal / ambient environment values — no `github.event.*` or other attacker-controlled input reaches this string. `SECANTUS_PGO_DISABLE` / `SECANTUS_PGO_GENERATE` are documented escape hatches, both env-only. `c4873cb0` is a same-day follow-up fixing a real build regression (the PGO `RUSTFLAGS=` assignment was clobbering cibuildwheel's ambient `-Ctarget-feature=-crt-static`, breaking every musllinux wheel build) — the fix composes ambient-then-PGO flags; verified via the diff that the compose order is ambient-first, ambient-value-preserved-when-empty.

No `permissions:`/secrets/pin changes.

All three changed workflows retain scoped `permissions:` blocks (`release-binaries.yml`: `contents: write` only, needed to attach release assets; `test.yml`: `contents: read`), and none interpolates `github.event.*` directly into a new `run:` block (the pre-existing `release-binaries.yml` `INPUT_TAG` env-var pattern for `workflow_dispatch` inputs, reviewed in prior cycles, is untouched by this diff).

Reviewed and sound. No finding.

### W1 (carried forward, still open — 7th consecutive cycle) — Two non-poison-tolerant `.lock().unwrap()` sites remain on the Rust oplog mutex

**File:** `crates/secantus-storage/src/lib.rs:3878` and `:3957` this cycle (line drift only, from this cycle's +162 lines earlier in the file — re-confirmed by direct grep of every `self.oplog.lock()` call site: this cycle's substantial async-oplog-coalescing addition correctly uses the poison-tolerant `unwrap_or_else(|e| e.into_inner())` pattern throughout its new code — `persist_group`'s `advance_written_seq` call included — but the same two pre-existing `live_count` accessors in `prune_oplog` — its early-out read and its post-prune decrement — still use bare `.lock().unwrap()`).

Already tracked as open issue [#593](../../../../issues/593), filed 2026-07-21, unfixed across **seven** consecutive review cycles (07-21 through 07-27) — including two of those cycles (07-26, 07-27) adding substantial new correctly-poison-tolerant lock acquisitions on this exact mutex without touching these two sites.

**Recommendation:** unchanged — convert both sites to `self.oplog.lock().unwrap_or_else(|e| e.into_inner())`. The grep-based CI gate recommended in the last six reports (`! grep -rn '\.lock()\.unwrap()' crates/secantus-storage crates/secantus-commands` outside `#[cfg(test)]`) remains unimplemented after seven nightly re-discoveries.

### W2 (carried forward, still open — 4th consecutive cycle) — `drop_index` / `drop_all_indexes` still lack the collection lock that `create_index` gained on 2026-07-24

**File:** `src/secantus/storage.py:5617` (`drop_index`) and `:5734` (`drop_all_indexes`) — re-confirmed present by direct read this cycle: both still open only `with self._lock:`, never `self._coll_lock(db, coll)`.

Already tracked as open issue [#635](../../../../issues/635), filed 2026-07-24. No commit this cycle touched `storage.py`'s locking discipline (the two `storage.py` diff hunks this cycle are the change-stream `read_oplog_scan` fix, unrelated to index-drop locking) — the hazard described in the 2026-07-24/25/26 reports is unchanged: a concurrent `insert`/`update`/`delete` (which takes `_coll_lock` first) is not excluded by `drop_index`'s `_lock`-only critical section.

**Recommendation:** unchanged — `with self._coll_lock(db, coll), self._lock:` in both methods, plus a regression test mirroring `test_ddl_and_crud_never_deadlock_and_index_stays_complete` for the drop path.
