  `zip(..., strict=True)` with no prior length check — malformed

  `actions/checkout@v7`, `astral-sh/setup-uv@v7`, `actions/upload-artifact@v7`
  to moving major-version tags. `workflow_dispatch`-only, `contents: read`,
  zero `secrets.*` — low blast radius. Unchanged.
- **I4** — The dead top-level `rust/` spike directory is still git-tracked
  and outside `pyproject.toml`'s sdist exclude list — harmless bytes riding
  the sdist, never compiled. Unchanged.
- **I5** — `#750`'s tracker issue (Rust `pending_async` oplog buffer size
  cap) remains open despite being verified fixed in twelve consecutive prior
  reviews; nothing in this window's diff touches
  `crates/secantus-storage/src/lib.rs`'s buffer logic (`secantus-storage` had
  zero diff this window). Left open per this run's "review, document, file
  only" scope.
- **I10** — MongoBleed (CVE-2025-14847, real `mongod`'s `OP_COMPRESSED`+zlib
  decompression buffer-size mismatch) remains not applicable: `wire.py` and
  `crates/secantus-wire` are both unchanged this window and both still only
  parse `OP_COMPRESSED` far enough to reject it outright. Unchanged.
- **I11 (new)** — The new `sql/subms.py` sub-millisecond-timestamp feature
  stores its microsecond remainder in a `__us_<field>` hidden document field
  (`companion_field`), distinguished from real user columns only by the
  `__`-prefix convention shared with expression indexes. Reviewed for
  injection/collision risk: the field is written and read only through
  `carry_subms`/`subms_update_ops`/`unwrap_composite` (all internal,
  non-attacker-reachable call sites — a SQL client never names this field
  directly, since the SQL parser maps column names to their catalog-declared
  storage field, not to arbitrary hidden keys), so a user cannot forge or read
  another row's companion value through the SQL surface. A determined client
  connecting via the **Mongo** wire protocol to the same underlying collection
  *could* write a sibling `__us_<field>` key directly (Mongo has no notion of
  the SQL catalog), which would desync the companion from its column and
  surface a wrong sub-millisecond remainder on a subsequent `SELECT` — a
  cross-protocol data-integrity quirk, not a privilege or memory-safety issue
  (the worst case is a wrong microsecond value in a column the same
  credentials could already read/write via the Mongo path). Posture note, not
  actionable as a vulnerability; consistent with the project's documented
  single-store, dual-protocol design (both protocols share one underlying
  document store by design, per `CLAUDE.md`).
