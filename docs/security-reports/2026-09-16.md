## 🔴 CRITICAL (Immediate action required)

All three unchanged, re-confirmed by direct read against current HEAD (not
inherited from the prior report):

- **#995** — `crates/secantus-wire/src/lib.rs:113-138` (`Header::body_len`).
  Re-read in full: `if (self.message_length as usize) < HEADER_SIZE` casts
  the signed `i32` to `usize` first — `message_length = -1` sign-extends to
  `usize::MAX` on 64-bit, which is not `< HEADER_SIZE (16)`, so this guard
  passes. The second guard, `if self.message_length > MAX_MESSAGE_SIZE`,
  compares the raw signed `i32` — `-1 > 48_000_000` is false, so it also
  passes. The function returns `Ok(self.message_length as usize -
  HEADER_SIZE)` = `usize::MAX - 16`, feeding an oversized allocation from one
  unauthenticated 16-byte frame on the accept path. **Not fixed.**

- **#1160** — `src/secantus/commands.py`. `"bulkWrite": _bulk_write` is
  registered at line 8646 in `_HANDLERS`; grepping `_COMMAND_ACTIONS` and
  `_NO_PRIVILEGE_COMMANDS` for `"bulkWrite"` still returns zero matches in
  either table. Dispatch's authorization check has no `else` branch for an
  unmapped command, so `bulkWrite` continues to run with no RBAC check under
  `--auth`. **Not fixed.**

- **#977** — `src/secantus/query.py:1407-1416` (`_MAX_REGEX_PATTERN_LEN =
  1000`, `_compile_regex`). Still only a length guard before an unguarded
  `re.compile`; a second bare `re.compile` call at line 1467 has no cap at
  all. No backtracking-depth or match-time budget. A 6-character pathological
  pattern (`(a+)+$`-shaped) is far under the 1000-char ceiling and still pins
  a CPU core via CPython's `_sre`, which never releases the GIL mid-match.
  **Not fixed.**
