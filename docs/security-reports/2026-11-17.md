## 🔴 CRITICAL (Immediate action required)

### New this cycle

- **`ALTER TYPE ... ADD/DROP/ALTER/RENAME ATTRIBUTE` on a composite type has
  no ownership check at all** (high/high, overall high — a fourth instance
  of this codebase's recurring missing-privilege-check pattern, now extended
  from statements to a wholly different object kind).
  `secantus_pgplan::privileges::sql_relations_uncached`
  (`crates/secantus-pgplan/src/privileges.rs:254-311`) has no match arm for
  `AlterTableStmt` (how `ALTER TYPE ... ATTRIBUTE` parses, confirmed via
  `crates/secantus-pgplan/src/typed_tables.rs:122`'s `plan_alter_type`), so
  it falls into the trailing `_ => {}` and the generic privilege gate
  (`crates/secantus-pg/src/lib.rs:17402`) never sees it. Independently,
  composite-type ownership is **never recorded at all**: the `CREATE TYPE`
  catalog document (`crates/secantus-pg/src/lib.rs:43895-43904`) has no
  `owner` field, and `PgHandler::object_owner`
  (`crates/secantus-pg/src/object_acl.rs:288-313`) has no `"type"` branch —
  a lookup falls back to the **calling** session's own username. Neither
  `PgHandler::alter_type_attributes` nor `rename_attribute_cascade`
  (`crates/secantus-pg/src/composite_alter.rs:30-260, 264-304`) nor the
  `rename_attribute` helper (`crates/secantus-pg/src/renames.rs:793-853`)
  perform any owner/role comparison. Net effect: any authenticated,
  non-superuser role can `ALTER TYPE <any composite type it does not own>
  DROP ATTRIBUTE <field>` (or ADD/ALTER/RENAME), and `rewrite_type_values`
  (`composite_alter.rs:352`) immediately rewrites every stored value of that
  type across **every table in the database**, regardless of who owns those
  tables — a cross-tenant destructive write with zero privilege required.
  This codebase already has the correct idiom elsewhere (`owned_or_superuser`,
  `crates/secantus-pg/src/opclasses.rs:1330`, used for opclass/opfamily
  drops) — it was simply never applied to composite types.
  **Independently confirmed** by a fresh verifier, who corrected one
  line-number offset and traced the full path from the generic
  `check_sql_privileges` entrypoint through every sink.
  **Fix:** record the creating role as `owner` on the composite-type document
  at `CREATE TYPE` time; add a `"type"` branch to `object_owner` that reads
  it; call `owned_or_superuser` (or equivalent) at the top of
  `alter_type_attributes`/`rename_attribute_cascade`/`rename_attribute`,
  raising 42501 otherwise. Separately, add an `AlterTableStmt` arm to
  `sql_relations_uncached` (shared root cause with the already-filed DDL
  ownership gap).
  **Filed as a new issue** (no duplicate found).

- **Unbounded recursion in the new `$redact`-safe-portion walker
  (`hoist.rs`) lets any aggregate client crash the server via stack
  overflow** (medium/high, overall high).
  `redact_safe_portion()` (`crates/secantus-commands/src/explain/hoist.rs:1084-1138`,
  new this window, RM-580) recurses once per `$or` branch and once per
  `$and` member of a client-supplied `$match` filter, with no depth counter
  anywhere in the function, its callers, or the BSON decode path that
  produces the filter. It runs via `copy_matches_ahead_of_redacts` /
  `list_matches_ahead_of_redacts` inside `hoist()`, called from
  `hoist_runnable()` at `crates/secantus-commands/src/aggregate.rs:818` —
  **the plain, non-`explain` aggregate execution path**, for essentially
  any ordinary pipeline. No layer above it bounds filter nesting depth: not
  `secantus-wire`'s `validate_bson` (length-only), not
  `secantus_core::bsondoc::from_bytes` (the shared command-document decoder,
  no depth tracking), and not this codebase's one nesting-depth guard
  (`MAX_NESTING_DEPTH = 180`, `crates/secantus-commands/src/crud.rs`, scoped
  only to insert/update document bodies). The connection-handling thread
  (`crates/secantus-server/src/lib.rs`, one `thread::spawn` per connection,
  no `stack_size` override) uses the default OS stack; a Rust stack overflow
  aborts the **whole process**, not just one connection — and with this
  server's default `require_auth: false`, no credential is required at all.
  This is the same vulnerability shape as the independently-confirmed
  2026-11-11 CRITICAL in this same file (`renameable`/`under_root`, for
  `$replaceRoot`), reachable here through a broader, more general path.
  **Independently confirmed** by a fresh verifier, who traced the full call
  chain from wire decode through to the recursion root.
  **Fix:** add one generic BSON nesting-depth guard (mirroring mongod's
  `BSONDepth::kDefaultMaxAllowableDepth`) at the single choke point where
  every incoming command document is decoded
  (`secantus_core::bsondoc::from_bytes`), rather than bespoke per-walker caps.
  **Filed as a new issue** (no duplicate found).

  vulnerable to this real PostgreSQL composite-type-confusion CVE's

  `check_cached_result_type` (`crates/secantus-pg/src/lib.rs:7413-7480`) is

  raising `0A000 cached plan must not change result type` rather than
